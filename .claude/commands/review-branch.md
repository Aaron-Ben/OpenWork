审查当前改动，结果用中文。本命令只审查，不修改文件。

## 1. 范围与脏文件分类

- 参数为空：`git diff dev...HEAD` 加上工作区与暂存区的改动。
- 参数为分支名：用它替换 `dev`。
- 参数为 `staged`：只审 `git diff --cached`。

先运行 `git status --porcelain`，把每个脏文件分到三类之一：

- **本次改动**：进度文件里当前工作包涉及的，或本次会话改过的；
- **无关改动**：属于别的工作包或别处的工作，本次不提交；
- **拿不准**：列出来问用户，不要猜。

`docs/raw.txt` 永远属于无关改动；如果它被暂存了，列为阻塞问题。

## 2. 只列会阻止合入的问题

每条写清：

1. 文件与行号；
2. 错在哪；
3. 怎么证明它会出错：给出具体输入或操作步骤，以及错误的结果。

写不出第 3 点的不算阻塞问题，放到"存疑"里，并说明查过哪里。风格、命名、可选的重构不要列。

## 3. 除了正确性，逐项核对

- **设计文档**：改动涉及的数字、清单、行为边界是否与 `docs/` 下的设计文档一致。代码与文档不一致、而进度文件里没有对应决策的，列为阻塞。
- **数据库**：新迁移与 SQLx 读写是否符合 `.claude/rules/database.md`，包括运行其中"回归检查"的两条 grep。
- **测试**：新行为有没有测试；postgres 测试是否依赖 `TEST_DATABASE_URL`；有没有为了通过而放宽的断言。
- **权限与沙箱**：凡是涉及路径判定、Seatbelt profile、越界授权的改动，检查大小写、符号链接、`..`、不存在的路径这几类输入。
- **越界改动**（AGENTS.md）：
  - 有没有顺手整理了任务不要求的代码；
  - 有没有为还不存在的情况加抽象、配置或扩展点；
  - 有没有为不可能出现的状态加兜底；
  - 有没有留兼容路径、回退开关或"以防万一"的旧代码；
  - 有没有改了验收条件没提到的文件；
  - 有没有在调用处打补丁，而不是在行为所在处修。

## 4. 给每个问题标处理方式

- **可直接修**：机械、局部的问题，例如断言错、漏了导入、死分支、漏改的调用点。
- **需要决定**：涉及设计判断，例如共享概念的命名、模块边界、公共接口、行为该放在哪一层。写下证据和建议，不要自行改；修复会波及本次范围以外的文件时，也归这一类。

## 输出

```text
审查范围：<基准>…<当前>，N 个文件

脏文件
  本次改动：…
  无关改动（不提交）：…
  拿不准：…

阻塞问题
1. [可直接修] path/to/file.rs:42 — <错在哪>
   复现：<输入/步骤> → <错误结果>
2. [需要决定] … — 建议：…

存疑（未能确认）
- …（查过哪里）

结论：可以提交 / 修完上面 N 条再提交
```

没有阻塞问题时直接写"阻塞问题：无"。
