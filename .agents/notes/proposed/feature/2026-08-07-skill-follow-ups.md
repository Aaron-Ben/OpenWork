# Agent Note: Skill 的后续能力

Status: proposed

## 问题

当前 Skill 只读，只有一个用户级根。发现靠采样时的扫描，目录超出预算时整条丢弃。下面这些需求已经提出，但都没有设计。

## 提议

按需要程度排序。开始任何一项前，先为它单独写一份 proposed Agent Note。

1. **Desktop 编辑器。** 文件树按需加载、SHA-256 乐观并发、原子写入、新建、删除、fork、删除确认、编辑态与只读态。这是一个独立项目。
2. **project skill。** 先决定仓库信任、父目录扫描与状态标识，再决定同名覆盖。不要顺手扫描仓库里的 `.agents/skills/`。
3. **文件监听器。** 当前依靠采样时的扫描与列表的刷新按钮。
4. **目录超预算时两级降级。** 先截断描述，再丢弃 skill。skill 数量少时没有区别。
5. **参数化调用、别名表压缩格式、按模型开关。**

当前行为见 [skills.md](../../../../docs/subsystems/skills.md)。

## 验收条件

- 每一项在实现前都有自己的 proposed Agent Note，写明验收条件。
- project skill 的 Agent Note 写明仓库信任规则与同名覆盖规则。
- 编辑器的 Agent Note 写明并发写入与原子写入怎样验证。

## 风险

- project skill 让仓库内容进入模型的目录，扩大提示注入面。
- 编辑器写入 skill 根。它必须是用户的操作，不能经过模型的工具；模型工具对 skill 根的写保护保持不变。
