# Agent Note: 压缩失败的处理

Status: proposed

## 问题

摘要采样失败时，当前做法很粗：任何失败都用同一份输入重试，最多三次（[compaction.md §3.3](../../../../docs/subsystems/compaction.md)）。每次失败已经按 `degenerate / deterministic / input_overflow / transient / timeout` 分类写进 Trace，但重试循环不读这个分类。

由此产生三个缺口：

- 鉴权失败、模型不存在这类确定性错误，也会白白重试三次。
- 自动压缩没有失败记录。同一个 Session 对几乎相同的输入失败后，下一个 Turn 会再次触发同一条失败路径。
- 摘要输入本身超出模型窗口时，只有原样输入这一层，没有办法缩小输入。

## 提议

1. **按分类决定是否重试。** 短暂失败允许重试：限流、网络、5xx、偶发的不合格摘要。确定性失败立即停止：鉴权失败、模型不存在、schema 无效、输入必然超窗。
2. **自动压缩的失败暂停。** 为每个 Session 持久化失败指纹、连续失败次数和下一次允许的时间。在预算明显变化、冷却结束或用户执行 `/compact` 之前，暂停自动触发。手动压缩始终可用，并返回真实错误。
3. **输入裁剪。** 增加 `verbatim_fitted` 一层：按窗口选取能放下的连续区段。它会改变摘要的事实来源与可追溯性，所以实现前先定义保留优先级与测试矩阵。修剪旧工具结果（[compaction.md §2](../../../../docs/subsystems/compaction.md)）已经在摘要之前处理了超大的工具结果。

## 考虑过的方案

**维持现状的粗粒度重试。** 这是当前实现。它简单，并且偶发失败通常能在重试中恢复。代价是确定性失败浪费时间，以及自动压缩反复失败。

## 验收条件

- 确定性失败只采样一次，压缩立即失败，错误码可读。
- 短暂失败仍最多重试三次。
- 自动压缩对同一指纹连续失败后，在解除条件满足之前不再触发；手动压缩照常执行。
- 摘要输入超窗时，`verbatim_fitted` 按定义的优先级裁剪，测试矩阵覆盖每一种保留优先级。

## 风险

- 分类错误会让本可恢复的失败不再重试。
- 暂停自动压缩后，请求可能直接 overflow。overflow 压缩也被暂停时，Turn 会失败，用户需要手动压缩。
- 输入裁剪之后，摘要不再覆盖全部历史。用户与模型需要知道哪一段被省略了。
