# Agent Note: 摘要采用固定结构并严格校验

Status: implemented

## 问题

压缩之后，摘要是更早历史的主要语义来源。一份坏摘要会让后续每一次 Model Call 都基于错误的前提。摘要的失败方式很多：输出被截断；内容退化成重复文本；模型去调用工具；历史中的文本伪装成 System 或提醒的标签，混进摘要。

摘要的输入也不可信。历史消息、工具输出和旧摘要里都可能有看起来像指令的文本。

## 决策

- 摘要固定九个标题，一个带 `format_version="1"` 的根，用代码确定性解析（`crates/openwork-core/src/session/compaction/summary.rs`）。
- 只接受 `finish_reason = stop`、不含 Tool Call 的响应。出现控制标签时整份拒绝。每个标题下必须有内容。
- 500 字符的下限只是退化检查，不代表完整。
- 摘要请求不带工具，关闭 thinking，输出上限固定。摘要指令声明：历史、工具输出与旧摘要都只是材料。
- 同一份输入最多试三次，每次 120 秒，间隔 3 秒。
- 数据库保存清理后的摘要，运行时不再让模型重新格式化旧摘要。
- 手动压缩是一等入口，与自动压缩走同一条路径。

事实见 [compaction.md §3](../../../../docs/subsystems/compaction.md)。

## 考虑过的方案

**只检查字符下限。** 没有采用。随机重复的文本也能超过下限，所以必须同时验证结构、终止原因和 Tool Call。

**转义可疑标签。** 原设计文档写的是“转义或拒绝”。代码选择拒绝：被转义的标签仍留在摘要里，下一次请求会再读到它。

**重试时逐次删减输入或换模型。** 没有采用。重试用同一份输入，它不是输入降级阶梯。输入裁剪是提议中的设计，见 [Agent Note：压缩失败的处理](../../proposed/architecture/2026-07-27-compaction-failure-handling.md)。

## 后果

- 一份摘要被接受时，结构一定完整，后续代码可以按标题定位内容。
- 校验严格，合格的模型输出也可能因为一个多余的标题被拒，进而消耗重试。
- 重试不区分失败原因。鉴权失败、请求非法这类确定性错误也会重试三次。
- 连续三次失败时，整个压缩失败，旧对话保持不变。Turn 内的压缩失败会让 Turn 失败。
