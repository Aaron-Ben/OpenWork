# Agent Notes

Agent Note 记录一项影响本仓库的决策或提议。它保存代码与设计文档不保存的内容：为什么这样定，放弃了什么。本文规定 Agent Note 的位置、写作时机和文件格式。

做法来自 DSH 的 `.agents/notes/README.md`。

## 位置与命名

路径是 `{生命周期}/{类别}/yyyy-mm-dd-主题.md`。主题用英文短横线连接的小写词。

生命周期是顶层目录。状态变化时，把文件移到对应目录：

- `proposed/`：提议，还没有实现，或只实现了一部分。
- `implemented/`：决策已经实现。文件必须与当前代码一致，见下文“保持与实现一致”。
- `rejected/`：提议被否决。只有它的理由能防止一个容易犯的错误时，才保留它。否则删除。

类别是第二层目录，从下面的封闭集合中选一个：

| 类别 | 范围 |
|---|---|
| `feature` | 新增用户或模型能用的能力 |
| `bug-fix` | 修正缺陷，或补上事故暴露的缺口 |
| `simplification` | 删除代码、行为或接口，不增加能力 |
| `architecture` | 关于发布代码结构的决定：crate 关系、所有权、运行时词汇 |
| `process` | 代码周围的工具、规则与流程，不涉及运行时行为 |
| `testing` | 测试设施与测试策略 |

文件名中的日期是这个主题第一次被提出的日期。Agent Note 之间用相对 Markdown 链接互相引用。不要建索引文件：直接浏览目录或搜索。

## 何时写

- 只为长期有效的决策理由写 Agent Note。代码、测试和设计文档已经说明的内容，不要再写。
- 机械改动与局部改动不写，局部界面调整也不写。
- 已有 Agent Note 负责这项决策时，更新它，不要新建一份重复的。
- 新建 Agent Note 前，搜索 `implemented/` 中覆盖同一决策的旧文件。完全被取代的旧文件，按下文“取代”处理。
- 设计文档写“是什么”：行为、数字、清单、验收。Agent Note 写“为什么”：问题、放弃的方案、代价。两者不重复，互相链接。

## 文件格式

### 开头

每份 Agent Note 的前三行固定为：

```markdown
# Agent Note: <标题>

Status: <状态>
```

状态只有三种写法，并且必须与所在目录一致：

- `Status: proposed`
- `Status: implemented`
- `Status: rejected — <一行否决理由>`

状态行不写日期，也不写括号说明。

### 正文结构

正文一律以 `## 问题` 开始。这一节写动机，不提解决方案也能读懂。固定小节只用下面的名称。专门的技术小节（表结构、协议字段）可以放在固定小节之间。

`proposed/` 的结构：

```markdown
## 问题
## 提议
## 考虑过的方案
## 验收条件
## 风险
```

`implemented/` 的结构：

```markdown
## 问题
## 决策
## 考虑过的方案
## 后果
```

- `## 决策` 用现在时描述已经实现的状态。给出代码路径与符号，并链接负责的设计文档章节。
- `## 后果` 写这个取舍的代价，也写它带来的好处。
- `implemented/` 中不能出现 `## 提议`、`## 计划`、`## 验收条件`。

`rejected/` 保留提议时的全部小节，否决理由只写在状态行。

### 考虑过的方案（必需）

每份 Agent Note 都有 `## 考虑过的方案`。每个真实的备选方案写一段，用加粗开头，并写明它为什么没有被采用。只记录真实讨论过的方案，不要编造。原始记录里没有备选方案时，写这一行：

```markdown
<!-- agent-note: 原始记录没有备选方案 -->
```

### 来源

引用参考项目的做法时，写出该项目里的文件路径。没有读过源码的内容，标为“未确认”。

## 保持与实现一致

- 代码改动了 Agent Note 提到的路径、符号、默认值或机制时，在同一个改动里更新 Agent Note。直接改写过时的事实，不要追加变更历史。
- 这只允许更新事实，不允许改写决策。决策反转时，新建一份 Agent Note，并与旧文件互相链接。

## 生命周期转换

- `proposed/` → `implemented/`：修改状态行。把 `## 提议` 改写为现在时的 `## 决策`。把验收条件与风险并入 `## 后果`。
- `proposed/` → `rejected/`：只在状态行加否决理由。之后不再修改这份文件。

## 取代

- 完全被取代的 implemented Agent Note，可以并入新的负责文件，然后删除。删除前，新文件必须保留旧文件中所有独有的理由、备选方案、后果与验证。修复所有指向旧文件的链接。
- 部分取代时，两份文件都保留，并互相链接。

## 不再有指导价值时

目前不设归档目录。一份 implemented Agent Note 的理由不再能指导以后的工作时，删除它。如果它还记录了某个被放弃的方案或某条安全规则，就保留它。
